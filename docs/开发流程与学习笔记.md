| 技术 | 作用 | 类比前端 |

## 二、后端分层架构（最重要的概念）

后端代码按职责分层，就像前端的"页面 → 组件 → 状态"分工：

```
src/
├── app.ts              入口（大门）：创建服务器、装中间件、挂路由
├── routes/             路由表（翻译官）：URL 路径 → 处理函数
├── controllers/        控制器（业务员）：具体业务逻辑
├── middlewares/        中间件（安检员）：拦截/校验
└── lib/prisma.ts       数据库连接单例
```

**职责边界（记住这句话）：**
- **routes 只做映射**：哪个地址 → 哪个函数。不写业务。
- **controllers 写业务**：接收请求 → 校验 → 操作数据库 → 返回结果。
- **middlewares 做拦截**：在请求到达 controller 之前先处理（比如验 token）。

## 三、一次请求的完整流转

前端发 `POST /api/messages` 为例：

```
① 前端请求
   ↓
② app.ts 中间件：helmet（安全头）→ cors（跨域）→ express.json（解析 body）→ 请求日志
   ↓
③ app.ts 按前缀 /api/messages 找到 message.routes
   ↓
④ message.routes 里匹配 POST / → 先过 authMiddleware（验 token）
   ↓
⑤ authMiddleware 验证通过，把用户信息挂到 req.user，放行
   ↓
⑥ controller.addMessage 执行业务（校验参数 → 防越权 → 写库 → 返回）
   ↓
⑦ 返回 JSON 给前端
```

**一句话：请求从"大门"进，过"安检"，由"翻译官"指路，最后由"业务员"干活。**

## 四、阶段一：注册登录

### 4.1 接口

| 接口 | 地址 | 方法 | 是否登录 | 作用 |
|---|---|---|---|---|
| 注册 | `/api/users/register` | POST | 否 | 创建账号 |
| 登录 | `/api/auth/login` | POST | 否 | 校验账号密码，发 token |
| 当前用户 | `/api/auth/me` | GET | 是 | 根据 token 返回登录者信息 |

### 4.2 开发思路：认证就三件事

1. **存**：注册时密码用 `bcrypt.hash()` 加密成密文入库（不存明文）
2. **发**：登录成功用 `jwt.sign()` 签发 token（内含用户 id/用户名/角色，7 天有效）
3. **验**：其他接口用中间件 `jwt.verify()` 验 token，通过则放行并挂 `req.user`

> 一句话：**注册 = 存加密密码；登录 = 比对密码 + 发 token；其他接口 = 验 token。**

### 4.3 代码阅读指引（按这个顺序读）

1. `src/app.ts` → 看路由挂载（大门分流）
2. `src/routes/user.routes.ts` → 看 `/register` 映射
3. `src/controllers/user.controller.ts` → **注册 5 步：校验 → 查重 → 加密 → 入库 → 返回**
4. `src/routes/auth.routes.ts` → 注意 `/me` 那行：`router.get('/me', authMiddleware, me)`（中间件夹中间）
5. `src/controllers/auth.controller.ts` → **登录 5 步：校验 → 查用户 → 比对密码 → 发 token → 返回**
6. `src/middlewares/auth.middleware.ts` → **5 步：读 header → 取 token → verify → 挂 req.user → next()**

### 4.4 测试步骤（Postman）

1. 注册：`POST /api/users/register`，body：`{ "username": "张三", "password": "123456" }`
2. 登录：`POST /api/auth/login`，同样 body → 返回里拿 `token`
3. 当前用户：`GET /api/auth/me`，Headers 加 `Authorization: Bearer <token>`

## 五、阶段二：聊天消息模块

### 5.1 接口

| 接口 | 地址 | 方法 | 是否登录 | 作用 |
|---|---|---|---|---|
| 新增消息 | `/api/messages` | POST | 是 | 向某会话写入一条消息 |
| 会话消息列表 | `/api/messages?sessionId=1` | GET | 是 | 拉取某会话全部消息（时间升序） |

> 本阶段只做消息**入库和查询**，不调用大模型（AI 流式接口在下一阶段）。

### 5.2 开发思路：四个关键词

1. **鉴权**：所有消息接口都先过 `authMiddleware`，保证是登录用户
2. **防越权**：查会话时必须同时满足 `id = sessionId 且 userId = req.user.id`，一条 `findFirst` 搞定"存在 + 归属"两个校验，防止访问别人的会话
3. **入库**：新增消息用 `chatMessage.create()`，只存校验过的字段
4. **查询**：用 `findMany` + `orderBy: { createdAt: 'asc' }` 按时间升序取历史记录

### 5.3 代码阅读指引

1. `src/controllers/message.controller.ts` → 新增消息 4 步 + 查询 4 步（注释都标了）
2. `src/routes/message.routes.ts` → 看中间件是怎么夹在路由里的
3. 重点理解 `req.user!.id`：`!` 是"非空断言"，告诉 TS"这里一定有值"（因为路由已过鉴权）

### 5.4 测试步骤（Postman）

> 前提：先登录拿 token，然后所有消息接口都要带 `Authorization: Bearer <token>`

1. 新增消息：`POST /api/messages`，body：`{ "sessionId": 1, "role": "user", "content": "你好" }`
2. 拉取消息：`GET /api/messages?sessionId=1`
3. 越权测试（验证防越权）：用 A 用户的 token 访问 B 用户的 sessionId，应返回 403"会话不存在"

## 六、数据库设计（schema 说明）

`schema.prisma` 是数据库的"蓝图"，定义了：

| 模型 | 用途 | 关键字段 |
|---|---|---|
| User | 用户 | username(唯一), password(密文), role |
| Document | 文档 | title, filePath, content, userId |
| ChatSession | 会话 | title, userId, documentId |
| ChatMessage | 消息 | role(user/assistant), content, sessionId |

**关键语法：**
- `@id @default(autoincrement())`：自增主键，**增删改查不要手动传 id**
- `@unique`：唯一约束（用户名不能重复）
- `@default(now())` / `@updatedAt`：时间字段自动维护，**不要手动传**
- `?` 可空；`@relation` 建立外键关系；`onDelete: Cascade` 父删子随删
- 枚举（enum）：限定字段只能取枚举值

## 七、开发流程规范（重点中的重点）

**改表结构的正确姿势（三步）：**

```
① 改 schema.prisma（加/改字段）
② npx prisma migrate dev --name 说明   → 生成迁移 + 改数据库 + 自动重新生成 client
③ 重启服务，测试
```

> ⚠️ **schema 是唯一事实来源。** 改了 schema 必须跑迁移，否则"代码 / 数据库表 / 生成的 client"三处会对不上（本项目就踩过：代码用 email，但表里根本没有 email 列）。

## 八、踩坑记录（新手高频错误）

| # | 坑 | 原因 | 正确做法 |
|---|---|---|---|
| 1 | `argument handler must be a function` | 控制器函数忘了写 `export` | 每个供路由用的函数前都要 `export` |
| 2 | `req.body` 是 undefined | Postman 没选 `raw → JSON`，没带 `Content-Type: application/json` | body 选 raw + JSON |
| 3 | 注册/登录查 email 报错 | schema/表里没有 email 字段，但代码用了 | 统一用 username 登录 |
| 4 | `import`/`export` 报错（verbatimModuleSyntax） | tsconfig 开了严格 ESM 检查 | 项目是 CJS，把该选项关掉 |
| 5 | 手改 `generated/` 目录 | 那是机器生成的产物 | 永远不手改，用 `prisma generate` 重新生成 |
| 6 | 返回 `price` 这类 Decimal 报错 | Decimal 类型不能直接 JSON 序列化 | 转字符串 `.toString()` 再返回 |
